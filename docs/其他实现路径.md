# 其他实现路径：为什么不是「AI 自动操作手机」

这份文档是一次完整的方案论证，回答三个问题：

1. 「AI 模拟操作手机」这条路能不能用？
2. 除了 ESP32，还有哪些办法解决「把新地址填进去」？
3. 各自的代价是什么，该按什么顺序试？

先给结论：**AI 能做，但用错了地方。** 它适合当「眼睛」（认出界面元素），不适合当「手」（决定往哪点）。

---

## 一、先把问题拆成三层

很多人把这件事看成一个问题，其实是三个，难度差了三个数量级：

| 环节 | 本质 | 难度 | 本项目采用 |
|---|---|---|---|
| 找出装了哪些购物 App、进地址页读地址 | **读** | 低 | 无障碍读屏（确定性脚本） |
| 判断哪条是新家、哪条是旧家 | **判定** | 低 | 关键词规则（区名/小区名） |
| 把新地址写进地址簿 | **写** | **高** | ESP32 硬件键盘 / 见下文方案 A～D |

**读和判定，AI 没有优势。** 关键词比对是确定的、可解释的、可复现的；换成模型反而引入不可复现的失败模式——同一个页面跑两次，结论可能不一样。这对「检测」类工具是致命的。

真正难的是第三层。它有三个坑：中文输入、省市区三级联动控件、写操作一旦出错代价极大。ESP32 只解决了第一个坑，这也是为什么它必需，但不够。

---

## 二、AI 模拟操作手机：能力、数据、代价

### 原理

不复杂，而且已经全部开源：

```
截图 → 视觉模型看懂界面 → 输出一个动作（Tap 坐标 / Type / Swipe / Back）
     → ADB 或无障碍执行 → 再截图 → 循环
```

智谱 2025 年 12 月开源了 Open-AutoGLM：9B 视觉模型（权重 MIT，框架 Apache-2.0），覆盖 50+ 高频中文 App，社区 2.6 万星。

### 纸面成绩与真实可用性

官方论文给出的安卓评测：AndroidLab 任务成功率 **36.2%**；热门中文 App 的常见任务人工评测 **89.7%**。

89.7% 听起来能用了，但**要看任务长度**。本项目的链路至少 6～8 步：

```
启动 App → 点「我的」→ 找到「设置 / 收货地址」→ 进入地址列表
→ 点某条地址 → 点编辑 → 定位「详细地址」输入框 → 输入 → 保存
```

若单步 89.7%，八步连乘约 **42%**。也就是说，一半以上的概率它会在中途迷路，而且**迷路时不会报错，它只会继续点下去**。

### 三个硬门槛

| 项 | 现状 |
|---|---|
| 本地部署 | 9B 权重约 20GB，需 24GB 以上显存（RTX 3090 级别） |
| 用云 API | 每步都要上传手机截图——截图里有姓名、手机号、完整地址、订单记录 |
| 项目成熟度 | Alpha，README 写明「仅供研究和学习」，最后提交停在 2026-03，279 个未关 issue |
| 现成 App | AutoGLM For Android + Shizuku 授权 + 智谱 BigModel 的 API Key，能跑，但成功率即上面的数字 |

**隐私这一条最致命。** 为了改一个收货地址，把「姓名 + 手机号 + 详细门牌 + 订单记录」的截图逐步上传到第三方推理服务，收益与代价完全不成比例。

### 结论

- ❌ 不做「AI 决定点哪里」的全自动版本，尤其不做写操作
- ✅ 可以做「AI 当眼睛、脚本当手」的混合实验：模型只负责从截图里认出「这是地址卡片」「那按钮是设为默认」，点击仍由确定性代码执行，且点前弹窗确认

## 三、不用 ESP32 的四条路

ESP32 解决的是「把中文地址填进输入框」。这条需求还有四种解法：

### 方案 A：输入法自定义短语 + 剪贴板（0 元，已具备）

就是 ESP32 方案里的「输入法展开」，去掉硬件。输入法建三条短语，地址页触发或长按粘贴。

- 成本：0
- 权限：无
- 覆盖：100%（任何 App、任何输入框、iPhone 也支持）
- 缺点：每个字段要手动点输入框、省市区手选，12 平台约 48 次点击
- 适合：搬家这种低频事件，或常用平台只有 3～5 个

**一句话：如果你一年搬一次家，这条就够了，不必买板子。**

### 方案 B：脚本 `setText()` 直接写入（纯软件，无需硬件）

AutoX.js 可往原生输入框写入文字，比模拟键盘更直接：

```
点进编辑页 → 定位「详细地址」输入框 → setText(新地址) → 人工确认后保存
```

- 优点：真自动化、中文无忧、零成本
- 缺点：仅对原生 EditText 有效，**Flutter / H5 / WebView 页面无效**（抖音、小程序类全废）；字段顺序需逐平台适配；**点错输入框可能把手机号写进姓名栏**
- 安全设计（必须）：一次只填一个字段 → 停在保存前 → 由人按下保存
- 适合：想「半自动、但保留人类闸门」的人

### 方案 C：PC 网页版 + 浏览器自动化

淘宝「我的淘宝 → 账户管理 → 收货地址」、京东「我的京东 → 账户设置 → 收货地址」、拼多多网页版都提供地址管理页。用 Playwright 驱动自己的 Chrome、自己的登录态，可读可改，中文输入无碍，全程有截图与日志。

**这是唯一能真正「一键改文字」的方案。**

**风险必须摊开说**：

- 京东《违规订单处理规则》禁止「以任何非京东认可的方式（如：机器人软件、蜘蛛软件、爬虫软件、刷屏软件等）访问或登录京东商城网站」
- 淘宝《软件许可使用协议》限定「仅限个人非商业自用」
- 平台具备识别自动化的技术手段（指纹、行为节律、滑块），一旦触发验证，麻烦大于收益

**降风险的做法**：只在搬家后跑一次、绝不设定时、串行不并发、随机间隔、遇验证码立刻停下交给人。当「一次性工具」用，不当「常驻自动化」用。

### 方案 D：PC 当键盘（scrcpy）

手机投屏到电脑，scrcpy 支持把电脑剪贴板粘贴进手机输入框。等于**用电脑充当那把 ESP32 键盘**：不花钱，中文走 PC 输入法。

- 缺点：需装 ADB、开 USB 调试，不能揣兜里用
- 适合：坐在电脑前集中改十几个平台

## 四、横向对比

| 方案 | 成本 | 能改文字 | 中文 | 覆盖 | 合规风险 | 维护 |
|---|---|---|---|---|---|---|
| A 输入法短语 | 0 | ✗ 人工粘贴 | ✅ | 100% | 无 | 无 |
| B 脚本 setText | 0 | ✅ | ✅ | 原生页约 70% | 中 | 中（逐平台适配） |
| C PC 自动化 | 0 | ✅✅ | ✅ | 网页端那几家 | **较高（ToS）** | 中 |
| D scrcpy | 0 | ✗ 人工粘贴 | ✅ | 100% | 低（自己的设备） | 低 |
| ESP32 | 40～60 元 | ✗ 人工按键 | ✅ | 100% | **无**（系统看来是键盘） | 无 |
| AI GUI Agent | 算力 / 隐私 | ✅ | ✅ | 视模型 | **高**（平台已封） | 高（Alpha） |

**为什么 ESP32 的合规风险是「无」**：在操作系统看来它就是一把普通键盘，不申请权限、不调无障碍、不注入事件。它和「自动化操控他人应用」在技术上是两件事。

---

## 五、建议的尝试顺序

按**痛感**排序，不按技术炫酷度排序：

1. **先用方案 A 撑过这次搬家。** 低频事件不值得为它上装备
2. **想省点击**：加方案 B（setText 半自动），保留「你按保存键」这道人类闸门，风险可控
3. **想全平台一把梭**：单独做 PC Playwright 工具，与手机项目分仓——它操作的是网页端账号，性质不同，风险也不同
4. **AI 版**：放 `experiments/`，README 明写「单步约 90%、长链路约 40%，不用于写操作」，只做读屏判定实验
5. **ESP32**：留给「不想授予任何软件权限」的人，它是唯一在 OS 层面零痕迹的方案

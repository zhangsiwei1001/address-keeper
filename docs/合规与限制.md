# 合规与限制

这份文档回答两个问题：**为什么这个项目不上架**，以及**如果你想要一个能上架的版本，应该长成什么样**。

## 一、为什么不上架

### 1. Google Play：禁止「自主决策」，只容忍「确定性规则」

官方政策原文：

> Apps using the Accessibility API for automation purposes must ensure that all actions performed on a user's behalf are for a narrow and clearly understood purpose. Any use of the Accessibility API that enables an app to autonomously initiate, plan, and execute actions or decisions is **strictly prohibited**. This does not prohibit deterministic, rule-based automation, where behavior follows a static, human-defined script.

来源：<https://support.google.com/googleplay/android-developer/answer/10964491>

两层含义：
- **规则版（本项目）**：属于政策允许的 "deterministic, rule-based automation"，但仍须提交无障碍权限声明、录制演示视频、做显著披露并取得用户同意
- **AI 判定版**：模型看屏幕后自行规划并点击，直接踩在 "autonomously initiate, plan, and execute" 上，没有通过的可能

政策还明确把 automation tools、password managers、launchers 排除在 `isAccessibilityTool=true` 之外，不能走「无障碍工具」豁免通道。

### 2. 平台侧：主流电商已在协议层面关闭自动化

豆包手机助手的屏幕自动化操作声明协议（SAEP）公示结束后，**155 款第三方 App 明确拒绝 AI 自动化操作**，其中阿里系 23 款（含淘宝、天猫）、腾讯 66 款、美团 11 款、快手 14 款。

来源：<https://36kr.com/p/4025601794101122>

即便上架成功，进淘宝地址页这一步也会被拦。**「能上架」和「上架后能用」是两件事，后者更致命。**

### 3. 国内应用商店：收录规则直接挡死

小米应用商店「暂不收录」清单包含：个人开发者身份发布的 App、主要功能依赖跳转第三方应用或网页获取功能的应用、外挂/作弊/破解类应用、非法获取或批量爬取个人信息的应用。

来源：<https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1354>

华为应用市场则要求 App 备案、软著、隐私合规材料齐全，并对权限逐项审核。

### 4. 系统层在持续收紧

- **Android 14** 引入 accessibility data sensitivity：App 可声明视图只允许「无障碍工具」读取
- **Android 16** 阻止这类服务对敏感视图注入模拟手势（`dispatchGesture`）
- **Android 17** 增强保护模式下，`AccessibilityService` 仅对通过验证的无障碍工具开放

来源：<https://mas.owasp.org/MASTG/knowledge/android/MASVS-PLATFORM/MASTG-KNOW-0143/>

**这条路今年能用，明年未必还在**。所以项目以「自用 + 源码」形式存在，而不是一个承诺长期可用的产品。

## 二、使用者须知

- 无障碍权限等于「能读取屏幕上的一切」，用完就关
- 自动化操作第三方 App 通常不被其用户协议鼓励；本项目只做「读取 + 设为默认」，仍有被风控、账号异常的理论风险
- 不要设成每日定时；搬家后跑一次、季度复查一次就够
- 输出 CSV 含地址信息，用完删除，不要随手分享

## 三、如果你想要能上架的版本

唯一可持续的结构是拆成两层：

| 层 | 内容 | 能否上架 |
|---|---|---|
| 商店版（合规） | 只管理**你自己的**地址库与核对清单：多地址版本管理、平台深链、搬家提醒、导出 CSV。不读其他 App、不模拟点击 | ✅ 可以 |
| 自动化层（不进商店） | 本仓库的 AutoX.js 脚本 / ESP32 固件，用户自行侧载 | ❌ 不上架 |

商店版的边界很清楚：**它是「你的地址」的管理器，不是「别人 App」的操控器。** 前者是效率工具，后者是外挂。

## 四、如果坚持要商业化

只有一条合法路径：**走平台开放接口**。淘宝、京东的开放平台对 ISV 有地址/订单能力，但需企业资质、应用审核、授权链路设计（且收货人信息普遍脱敏，只给 OAID）。成本远高于做工具本身。

# 地址管家（完整版）说明

`autojs/地址管家.js`：枚举购物 App → 逐个进地址页 → 判定 → （可选）把新地址设为默认。

## 能做什么、不能做什么

| 期望 | 情况 |
|---|---|
| 检测装了哪些购物软件 | ✅ 读系统应用列表，按名称关键词筛出，输出清单 CSV |
| 进去获取收货地址 | ✅ 自动点「我的」→「收货地址」，读全页地址文本 |
| 一键修改 | ⚠️ **只能“把地址簿里已有的新地址设为默认”**，不能改地址文字、不能新增地址 |

为什么只能到这一步：每个平台的编辑页表单结构不同（省市区多为三级选择器），要逐平台写适配，而且写操作一旦点错，可能把正确地址改坏、把包裹寄到旧地址。代价比“没改”大得多。

所以脚本的设计原则是：**只点“设为默认”，绝不碰地址文本**。

## 运行前准备

1. 装 AutoX.js（或 AutoJS Pro）
2. 开**无障碍服务**（读屏必需）
3. 允许“查看应用列表”。Android 11 以上需要 `QUERY_ALL_PACKAGES`；若清单为空，到系统设置给 AutoX.js 开应用列表权限
4. 改脚本顶部的 `NEW_KEYWORDS` / `OLD_KEYWORDS`：用区名或小区名，别用“XX市”这种两地共有的词

## 跑一遍会发生什么

```
枚举购物 App → 弹窗：“发现 N 个，是否开始”
   ↓
逐个 App：自动点「我的」→「收货地址」
   ├─ 成功 → 读地址 → 判定
   └─ 失败 → toast 提示手动点进去，最多等 2 分钟
   ↓
✔ 已是新地址        → 不用动
⚠ 新旧地址并存      → 尝试“设为默认”（逐条弹窗确认）
⚠ 只有旧地址        → 只报告，不动手（需你先加一条新地址）
需人工确认          → 特征词没命中，看原始文本调关键词
   ↓
输出 /sdcard/地址巡检/ 下两份 CSV
```

## 误点是怎么防的

1. 先用 `textContains(新地址特征)` 找到新地址所在行，取它的 **Y 坐标**
2. 再找所有“设为默认”按钮，**只点 Y 差 ≤110px 的那个**（同行判定）
3. 找不到就返回“该行取不到按钮，未动手”，绝不盲点
4. 每次点前弹窗确认（`CONFIRM_EACH_CLICK = true`）
5. 点完重新读页面，确认旧地址特征已消失，才标记为“已切换”

想更保守：`ALLOW_AUTO_SET_DEFAULT = false`，退回纯检测模式。

## 打包成 App（可选）

AutoX.js 自带打包功能：菜单选「打包」，填应用名、图标，产出 APK，装上就是桌面上的一个图标。

- 打包后仍需手动授予无障碍权限
- **无法上架应用商店**（原因见 [合规与限制.md](合规与限制.md)）
- 只能自用侧载，不要分发给别人——会把你的地址特征配置一起带出去

## 常见问题

| 现象 | 解决 |
|---|---|
| 清单是空的 | 应用列表权限没给；或 App 名称不在 `APP_NAME_PATTERN` 里 |
| 自动导航失败的多 | 各 App 的「我的」叫法不同，往 `autoNavigate()` 的 `tabs` 数组补词 |
| 一直“需人工确认” | 关键词不够准，把结果 CSV 的原始文本发 Issue |
| 点完没变化 | 有的平台“设为默认”要点两次或藏在“更多”里；这类先人工设一次，之后仅做检测 |
| 抖音/小程序读不到 | WebView 渲染，无障碍拿不到文字；需剪贴板兜底分支（Roadmap） |
